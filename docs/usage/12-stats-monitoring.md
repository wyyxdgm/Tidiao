# 12. 统计与监控

> 任务统计、花费追踪、调度器状态、跨项目全局看板。

## 概述

编排平台提供两个监控入口：`/stats` 花费统计页和 `/global` 全局看板。统计页展示任务状态计数、按标签/模型/日期的花费分解、调度器实时状态。全局看板跨项目展示所有任务的实时状态。侧栏角标显示各 scope 的运行中/待审核/总数计数。所有数据按当前用户隔离。

### 功能点：任务统计

- **是什么**：展示当前用户名下所有任务的各状态计数和花费汇总。
- **怎么用**：访问 `/stats`，顶部展示四张统计卡片：
  - **总花费**：所有未删除任务的 `cost_usd` 之和。
  - **总任务数**：各状态任务数量之和。
  - **平均每任务**：总花费 / 总任务数。
  - **今日花费**：当天完成任务的花费。
- **注意**：
  - 所有聚合按 `owner_id` 过滤，不会看到其他用户的数据。
  - 只统计未软删除（`deleted_at IS NULL`）的任务。
  - 花费数据来自任务完成时记录的 `cost_usd` 字段。

### 功能点：花费分解

- **是什么**：按标签、模型、日期三个维度分解花费。
- **怎么用**：在 `/stats` 页面下方查看三个图表：
  - **近 7 天花费**（柱状图）：每天完成任务的花费，缺失日期补 0。柱高按最大值等比缩放。
  - **按标签花费**（饼图）：将任务 `tags` 数组中的每个标签作为维度，花费按标签累加（一个任务多个标签会分别计入）。右侧图例显示标签名、金额和占比百分比。
  - **按模型花费**（水平条形图）：按任务使用的 `model` 字段分组，条形长度按最大值等比缩放。
- **注意**：
  - 标签花费：一个任务有多个标签时，其花费会分配到每个标签（不是平分，是每个标签都累加完整花费）。
  - 只有有 `tags` 字段且 `cost_usd` 非空的任务才参与标签统计。
  - 只有有 `model` 字段且 `cost_usd` 非空的任务才参与模型统计。
  - 按天统计基于 `completed_at` 字段，只统计最近 7 天。

### 功能点：调度器状态

- **是什么**：展示调度器的队列大小、运行数、最大并发，以及运行中和排队中的任务列表。
- **怎么用**：通过 `GET /api/stats` 获取调度器状态：
  - `queue_size`：当前排队等待的任务数。
  - `running_count`：当前正在运行的任务数。
  - `max_concurrency`：全局最大并发数（1-5）。
  - `running_tasks`：运行中任务列表（id + title）。
  - `queue_tasks`：排队中任务列表（id + title）。
- **注意**：
  - 调度器是单机共享的，队列中的任务 ID 跨所有用户，但 API 只返回当前用户拥有的任务标题。
  - 不属于当前用户的任务 ID 会原样显示（无标题）。
  - 此数据在统计页和全局看板中均可用。

### 功能点：全局看板

- **是什么**：跨项目跨版本展示当前用户的所有任务，支持筛选和实时更新。
- **怎么用**：
  1. 访问 `/global`，加载当前用户名下所有任务 + 项目列表 + 版本列表。
  2. 使用筛选栏按项目/版本过滤。下拉选项 ≥6 个时自动出现筛选框（R241）：输入即过滤、↑↓ 导航、Enter 选择、Esc 关闭；全站 Select 组件统一此行为，无需单独开启。🆕 **2026-11-02**：筛选框从「trigger 上方文档流」挪进**下拉面板顶部**——之前打开下拉会把宿主行（toolbar/表单）撑到近两行高，现在打开/关闭零布局位移。
  3. 支持三种视图：卡片视图、看板视图、聊天视图。
  4. 卡片和看板视图中每张卡片显示所属项目和版本名称。
  5. 订阅全局 SSE（`/api/events`），任务状态变更和费用更新实时推送到页面。
- **注意**：
  - 视图配置（视图模式、筛选条件等）持久化在 scope `global` 下，与单个项目版本的配置独立。
  - 聊天视图的新建任务使用筛选栏选中的项目/版本，未选时提示选择。
  - 聊天视图的新建输入区支持三种附件上传方式：📎 按钮、Cmd/Ctrl+V 粘贴板、拖拽文件到输入框（详见 [03-任务管理](./03-tasks.md)）。
  - 版本下拉根据选中的项目联动（只列出该项目的版本）。
  - 所有数据按 `owner_id` 隔离，只能看到自己的任务。

### 功能点：角标计数

- **是什么**：侧栏导航中各 scope（项目/版本）旁显示纯数字徽章，格式 `运行中/待审核/暂停`，三段斜杠分隔、各自状态色，全 0 整条隐藏。飞书 R36。
- **怎么用**：通过 `GET /api/stats/counts` 获取按 scope 分组的任务计数。
  - Key 格式：`projectId:versionId` 或 `projectId:`（无版本的任务）。
  - 每个 scope 返回 `running`（合并 queued+running）/ `reviewing` / `paused` / `total`。
- **注意**：
  - 计数按当前用户隔离。
  - 角标在侧栏导航树中实时显示（订阅 `/api/events` 的 `status_change` 触发重拉），帮助快速定位需要关注的任务。
  - 项目级徽章 = 该项目下所有版本 + unversioned 累加；无任务时回退显示版本数。
  - 全局看板入口也显示总体的运行中/待审核/暂停计数（同样格式）。
  - 颜色：运行中 = blue-500、待审核 = purple-600、暂停 = yellow-600；与 `STATUS_DOT` / 看板状态点视觉一致。

### 功能点：用量统计页（v41）

- **是什么**：`/usage` 页面，按 **小时 / 天 / 周 / 月 / 年** 看 cost、任务数、各模型用量。**普通用户也能看自己**（双口径）；admin 还能切到全平台或任意单个用户。
- **怎么用**：
  1. 侧栏点 📊「用量统计」进入（入口对所有用户开放）。
  2. 顶部下拉切换时间粒度；顶部三张卡片是**全量**总计（不受粒度和 limit 影响）。
  3. **admin 顶部多一个「用户范围」下拉**：「全部用户」/「仅我的」/「仅某用户」。普通用户无此切换器，永远只看自己。admin 切到「全部用户」时，页面底部多一张「按用户汇总」表，列出每个用户累计花费；点击列名可上滑到顶部切到该用户单独看。
  4. 标题旁的**口径徽标**自述本视图范围：紫色「全部用户」/ 灰色「仅我的」/ 蓝色「仅 <邮箱>」，与 `/api/stats/backlog` 面板同款。
  5. 「分区间用量」表格点某一行展开该区间的各模型明细。
  6. 底部「各模型总量」是全部任务按模型聚合。
- **注意**：
  - 数据来自 `GET /api/stats/usage?granularity=hour|day|week|month|year&limit=N[&owner=self|all|<user_id>]`，与 `/api/stats` **各自独立** —— 后者是 dashboard 固定视图，有巡检脚本在消费，不要合并。
  - 🔴 **分桶按 UTC+8**：DB 里 `created_at` 是 UTC 无时区标记，不换算的话「今天」的边界整体偏 8 小时。响应里带 `timezone: "UTC+8"` 字段，前端直接显示桶标签，**不要再 `new Date(bucket)` 转一次**。
  - 只统计 `deleted_at IS NULL` 的任务；`cost_usd` 为 NULL 一律当 0（库里确实有 NULL，是真实数据不是 bug），用 COALESCE 而不是过滤掉，否则任务数会跟着 cost 一起消失。
  - 模型口径 = `COALESCE(resolved_model, model, '(unknown)')`：`resolved_model` 是实际跑的模型，`model` 只是任务上写的意图且可能为 NULL。
  - ⚠️ **没有 input/output token 分列**：`tasks` 表只有 `context_tokens`（上下文规模）一列，所以「各模型用量」= 任务数 + cost 之和 + context_tokens 之和，**不提供 token 进出明细**。要提供得先加采集。
  - `limit` 上限 500；缺省按粒度给（hour 24 / day 30 / week 12 / month 12 / year 5）。
  - **权限边界（owner 参数）**：
    - 普通用户：缺省/显式 `owner=self` → 200，scope=mine。传 `owner=all` 或别人的 id → 403 `admin required`（错误文案保持不变，前端按它分支）。
    - admin：缺省/`owner=self` → 200，scope=mine（不放默认切到 all，避免误读）；`owner=all` → 200，scope=all，多带 `total.by_owner`（LEFT JOIN users，按 cost 倒序）；`owner=<存在的 user_id>` → 200，scope=owner；`owner=<不存在的 user_id>` → 404 `user not found`。
    - 未登录 401 在 admin 检查之前（顺序：auth 先于 role）。
    - SQL owner 条件三处必须同步（scoped CTE / totalRow / totalByModel）—— 漏一处桶和总量口径对不上。by_owner 不参与 SQL owner 过滤（它本身按 owner 分组，多加一层过滤会变 0）。

## 常见问题

**Q: 统计页的花费为什么和实际有出入？**
A: 花费数据来自任务完成时记录的 `cost_usd` 字段。如果任务异常终止（如进程被 kill），可能未记录最终花费。只有 `completed_at` 在最近 7 天内的任务才参与按天统计。

**Q: 全局看板能看到其他用户的任务吗？**
A: 不能。所有 API 和查询都按 `owner_id` 过滤，只能看到自己创建的项目和任务。

**Q: `/stats` 和 `/usage` 有什么区别？**
A: `/stats`（花费统计）是固定视图 —— 近 7 天花费柱图 + 按 tag/模型的饼图 + 调度器队列。`/usage`（用量统计）是可选粒度的时间序列表格，能按小时/天/周/月/年看。两者数据源是两个独立端点。

**Q: 用量页顶部的「总花费」和分区间表格加起来对不上？**
A: 正常。顶部卡片是**全量**总计，表格只是最近 `limit` 个区间。这样设计是为了避免把「最近 30 天的花费」误当成「平台一共花了多少钱」。

**Q: `/usage` 能看其他用户的用量吗？**
A: 普通用户不能 —— 顶部不会出现「用户范围」切换器，所有数字都只看自己的任务。**admin** 顶部多一个切换器：选「全部用户」看全平台（页面底部多一张「按用户汇总」表），选「仅 <邮箱>」看单个用户的。响应里始终带 `scope` 字段自述口径，标题旁的徽标告诉你是哪种视图。

- SPA `Stats.vue` 仿 master `Tabs.tsx:57` 行为，tab 切换持久化到 `?tab=`：
