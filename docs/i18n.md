## 技术约定（已定，勿改）

- `vue-i18n` Composition 模式；locale 文件按语言/域组织：`spa/src/i18n/locales/{zh-CN,en-US}/<域>.json`（glob 自动收集，新域 = 新文件，零注册）
- key 命名 `<域>.<子域>.<元素>`（如 `tasks.detail.approveBtn`）；域文件内容顶层就是域名（照抄 `login.json`）
- 语言偏好：localStorage `tidiao-lang`（默认 zh-CN）；`setLang/getLang` 在 `spa/src/i18n/index.ts`
- **代码注释保持中文，只翻译会渲染给用户的字符串**（模板文本、label、toast、错误 message、aria-label/title）
- 后端返回的 message（如 HttpError.message）原样展示不翻译；前端自有兜底文案走 t()

## 实测基线（2026-11-06）

- 182 个 spa 文件含中文 / 13,074 行含中文字符（大头是注释，不翻）；真实 UI 文案约 1.5-3k 条
- `src/app/**` 历史壳**不做**；`instance-title`（浏览器标签）暂不动；后端用户可见文案（邮件/intake 消息）W5 可选

## 每个 i18n task 的通用作业程序（agent 照此执行）

1. 读本文档 + 样板 `spa/src/views/LoginView.vue`（对照其 commit `2dc321e` 的 diff 更直观）
2. 迁移分派视图：script 里 `const { t } = useI18n()`，模板 `{{ t('域.key') }}`；新域先建 `locales/{zh-CN,en-US}/<域>.json` 两份
3. 中文注释一律不动；placeholder 是用户可见的也要进 locale（`you@example.com` 这类通用值除外）
4. 验证（显式 exit code）：
   ```bash
   cd spa && npx vitest run && ec=$?; echo "vitest exit=$ec"
   npm run build > /tmp/build.log 2>&1; ec=$?; echo "build exit=$ec"; tail -5 /tmp/build.log
   ```
5. commit：`feat(spa): i18n <域> (W<x>)` + 尾部撤销命令；push 到 main
6. 🔴 只动你的文件；发现共享文件（router / main.ts / 别人的域 json）需要改 → 写进 task 报告，不要自己改

## 踩坑记录（前人遗留，后来者必读）

- vue-tsc + vue-i18n 宽泛 messages 撞泛型推导 → `createI18n({...} as I18nOptions)`；`i18n.global.locale` 会被推导成 string → `WritableComputedRef` 断言（见 `spa/src/i18n/index.ts`）
- npm/vite 输出经管道（`| tail`）后 exit code 失真 → 必须显式 `ec=$?` 再判断成败
- spa 测试入口在 `spa/` 目录内跑（根 vitest exclude 了 spa/**）；spa/node_modules 缺失时先 `npm install --registry=https://registry.npmmirror.com`
